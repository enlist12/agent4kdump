# 重构 RAG 并按 PageIndex 的 Tree 模型重接历史经验检索

  ## Summary

  目标是把 src/agents/rag 从“一个 1000+ 行、把 PageIndex / 历史经验 / Linux background / 总结拼在一起的大文件”重构成职责清晰的模块，同
  时把 PageIndex 的使用方式改正确：

  - 不再要求用户提供 PAGEINDEX_DOC_IDS。
  - 不再把 PageIndex 当成对未知 doc_id 直接 chat_completions() 的服务。
  - 改为：把历史经验 markdown 语料交给 PageIndex 生成 tree，缓存 tree，本地用 LLM 做 tree search，提取相关经验。
  - Linux background 保留为独立通道，但从 PageIndex 和经验存储逻辑里拆出去。
  - 实现保持简洁，错误处理明确，不能静默误导用户。

  设计依据：

  - PageIndex SDK Tree (https://docs.pageindex.ai/sdk/tree)
  - PageIndex Chat SDK (https://docs.pageindex.ai/sdk/chat)
  - PageIndex API Endpoints (https://docs.pageindex.ai/endpoints)
  - PageIndex LLM Tree Search (https://docs.pageindex.ai/tutorials/tree-search/llm)
  - PageIndex Vectorless RAG Notebook (https://github.com/VectifyAI/PageIndex/blob/main/cookbook/pageindex_RAG_simple.ipynb)

  ## Key Changes

  ### 1. 改正 PageIndex 接法

  - 删除 PAGEINDEX_DOC_IDS 作为启动配置的要求；main.py 不再展示或校验它。
  - 删除当前 context_builder.py 中基于 chat_completions(doc_id=...) 的历史经验检索路径。
  - PageIndex 只负责“把 markdown 经验语料转换成 tree 结构”；不再依赖其 Chat API 做历史经验召回。
  - 保留的 PageIndex 配置只有：
      - PAGEINDEX_API_KEY
  - 删除无实际用途的 PAGEINDEX_MODEL 依赖，除非实现时确认某个 endpoint 真的需要；默认不保留。

  ### 2. 历史经验改成“语料构建 + tree 缓存 + tree search”

  - 保留现有 jsonl + md 历史经验存储思路，但把“经验持久化”和“经验检索”拆开。
  - 在经验写入后，额外维护一个聚合 markdown 语料文件，例如 cache/rag/history_corpus.md。
      - 每个 case 用稳定标题分段，包含 case_id、summary、root cause、trigger path、playbook、applicability、fix patterns 等可检索字段。
      - 语料组织按 markdown 标题层级写，便于 PageIndex 生成可搜索 tree。
  - 新增本地 tree 缓存元数据，例如 cache/rag/pageindex_tree.json 和 cache/rag/pageindex_state.json。
      - pageindex_tree.json：保存 PageIndex 返回的 tree 结构。
      - pageindex_state.json：保存当前 corpus hash、上次生成时间、生成状态、最近错误。
  - tree 生成策略固定：
      - 若本地 corpus 不存在或没有历史经验，直接跳过 PageIndex。
      - 若 corpus hash 未变化且本地 tree 缓存存在，直接复用，不重新请求 PageIndex。
      - 若 corpus hash 变化且存在 PAGEINDEX_API_KEY，调用官方 Markdown Processing API POST /markdown/ 重新生成 tree。
      - 若 corpus hash 变化但缺少 PAGEINDEX_API_KEY，明确告警并回退到本地 lexical retrieval，不使用过期 tree。
  - 召回策略固定：
      - 先用本地 LLM 对 PageIndex tree 做 tree search，选出相关 node_id。
      - 再从 tree 节点中提取 title / summary / text / line_num / node_id 组织成经验命中结果。
      - 如果 tree search 失败或 tree 不可用，再回退本地 jsonl 词法召回。

  ### 3. 按职责拆文件

  至少拆成以下 4 个职责明确的模块：

  - [context_builder.py](/root/agent4kdump/src/agents/rag/context_builder.py)
      - 只保留编排职责：提取 profile、拼 query、调用历史经验检索、调用 Linux background、总结最终 RAG 文本。
      - 不再包含 PageIndex HTTP 细节、经验落盘细节、tree 缓存细节。
  - src/agents/rag/experience_store.py
      - 负责 persist_success_case() 相关逻辑。
      - 负责 jsonl 读写、markdown case card 生成、聚合 markdown corpus 生成、hash 计算。
      - 对外提供：
          - persist_case(...)
          - load_records()
          - build_history_corpus()
  - src/agents/rag/pageindex_tree.py
      - 负责所有 PageIndex 相关逻辑。
      - 负责：
          - 校验 PAGEINDEX_API_KEY
          - 调 Markdown Processing API
          - 读写 tree/state cache
          - 暴露运行时状态
          - 执行 LLM tree search
          - 把选中的 tree 节点转成统一的 experience_hits
      - 对外提供类似：
          - sync_history_tree()
          - retrieve_from_tree(query, top_k)
          - get_runtime_status()
  - src/agents/rag/linux_background.py
      - 负责 Tavily/web 搜索 Linux background。
      - 从 context_builder.py 拆出 _collect_linux_background() 和相关 query 构造。
      - 与历史经验检索完全解耦。

  ### 4. 精简 AnalysisRAGManager 对外接口

  - 保留 AnalysisRAGManager 作为外部唯一入口，避免 main.py 和 workflow 大改。
  - AnalysisRAGManager 继续公开：
      - build_pre_analysis_context(crash_report, top_k=3)
      - persist_success_case(...)
      - get_pageindex_runtime_status()
  - 但其内部改为组合：
      - ExperienceStore
      - PageIndexTreeRetriever
      - LinuxBackgroundCollector
  - get_pageindex_runtime_status() 返回值改成围绕 tree 模式，而不是 doc_id/chat 模式：
      - enabled
      - api_key_configured
      - tree_cache_ready
      - tree_cache_stale
      - last_sync_status
      - fallback_reason

  ### 5. 启动提示与错误处理

  - main.py 启动摘要中不再出现 PAGEINDEX_DOC_IDS。
  - 显示内容改为：
      - PageIndex Enabled
      - API Key Configured
      - History Tree Ready
      - History Tree Stale
      - PageIndex Fallback Reason
  - 错误处理固定：
      - 缺 PAGEINDEX_API_KEY：明确提示“无法刷新 history tree，将回退本地经验检索”。
      - PageIndex 请求失败：记录错误并回退本地检索。
      - tree search 结果为空：允许回退 lexical retrieval。
      - 历史经验为空：不报错，返回无经验命中。
  - 去掉无关状态和无效配置，避免“看起来像启用了 PageIndex，实际没有”。

  ## Public Interfaces / Data Changes

  - 环境变量：
      - 删除 PAGEINDEX_DOC_IDS 的必填语义。
      - 默认删除 PAGEINDEX_MODEL 的运行依赖。
      - 保留 PAGEINDEX_API_KEY。
  - 新增本地缓存文件：
      - cache/rag/history_corpus.md
      - cache/rag/pageindex_tree.json
      - cache/rag/pageindex_state.json
  - AnalysisRAGManager.get_pageindex_runtime_status() 的字段语义调整为 tree/corpus 模式。
  - persist_success_case() 在保存 case 后，必须触发 corpus 更新；tree 同步可以在保存后尝试刷新，也可以标记为 stale 并在下次 retrieval
    前刷新。默认采用“保存后只更新 corpus 和 stale 标记，检索前懒同步”，减少写路径失败面。

  ## Test Plan

  不执行任何自动测试；按项目要求，本轮实现后不自行跑测试。验收场景按静态逻辑和代码路径覆盖设计：

  - 无历史经验：
      - build_pre_analysis_context() 返回空经验命中，不报错。
  - 有历史经验、无 PAGEINDEX_API_KEY：
      - 明确显示无法刷新 history tree。
      - 走本地 lexical retrieval。
  - 有历史经验、有 PAGEINDEX_API_KEY、无本地 tree：
      - 生成 history_corpus.md
      - 后续 retrieval 使用 tree search
      - 直接复用本地 tree cache
  - corpus 已变化但 API 调用失败：
      - 标记 tree stale
      - 回退 lexical retrieval
      - 不误报“PageIndex Active”
  - tree search 找不到节点：
      - 回退 lexical retrieval
      - 最终 RAG 上下文仍可生成
  - Linux background 通道关闭或 Tavily 缺失：
      - 历史经验检索仍可正常工作
      - 两个通道互不影响

  ## Assumptions

  - 本轮历史经验 corpus 采用“单个聚合 markdown 文档”方案，而不是“每个 case 一个远端 PageIndex 文档”。
      - 理由：当前目标是简洁可用；单文档 tree 最符合现有经验库结构，也避免再引入 doc_id 管理和远端文档搜索。
  - PageIndex 对本项目的合理定位是“结构化 tree 构建器”，不是“历史经验聊天服务”。
      - 因为官方 Markdown Processing API 返回 tree 结构而不是 doc_id，更适合结合本地 LLM 做 tree search。
  - 若后续历史经验量明显增大，再考虑把聚合 corpus 拆成分片文档；这不包含在本轮。
